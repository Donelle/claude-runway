# Files

What each file in the repository is for. The [README](../README.md) is the entry point; this table is kept here because it has a row per file and grows with every new module.

The MCP servers Claude Code launches (`*_mcp_server.py`) live in `mcpservers/`, apart from `tools/`, which holds the CLIs a person runs. `mcpservers/` must never get an `__init__.py` (and is not called `mcp`) so it cannot shadow the `mcp` SDK package the servers import.

| `tools/doctor.py`                 | CLI: `python tools/doctor.py /path/to/target-repo` reports any mismatch between the live shell and `.mcp.json`'s `local-compress` env block (`CLAUDE_RUNWAY_LMSTUDIO_URL`/`_MODEL`/`_TRACK_SAVINGS`), `compact` block (the LM Studio values) and `analytics` block (`CLAUDE_RUNWAY_SAVINGS_DB`) instead of leaving that silently split. | `libs/autowork_cost_lib.py`       | Shared, dependency-free derivation of `/cr-gh-autowork`'s per-ticket cost from subagent transcripts: usage per model (fresh input, cache creation, cache reads, output), tool calls and wall clock, linked to a ticket by agent id; plus matching old metrics rows to transcripts for backfill/compare. | `libs/pr_round_cost_lib.py`       | Shared, dependency-free, read-only reader that finds one pull request's review rounds in a session transcript and what Claude spent in each: a `copilot` round starts at the first feedback fetch that shows a new newest Copilot review (the user's own reviews are ignored, `latestReviews` is never read), a `local` round at each call to the codebase-reviewer's `review` tool. A Bash call counts as a feedback fetch in exactly two ways and nothing in a command is parsed: a result carrying the marker line `/cr-pr-feedback` prints (`pr-feedback-fetch: pr=<N> copilot-review=<id>`), taken as written (the skill prints it by running `echo` as its own Bash call after the four fetches, so it lands in a tool result; the same line in an assistant message is never read), or a command that matches, whole, one entry of a closed whitelist of the exact shapes the skills and the existing transcripts use (`gh api .../pulls/<N>/reviews`, `.../comments`, `.../issues/<N>/comments`, `gh pr view <N> --json ...reviews...`, with the `--paginate`/`--jq` forms). Any other command that names the PR's reviews or comments (wrapped in `timeout`, `env` or `if`, captured in `$(...)`, piped, redirected) is counted as unrecognised, not read; a new shape is added to the whitelist with a test row. Only a reviews fetch or the marker can start a round or supply a review id: a comments fetch (inline, issue, or `gh pr view --json comments`) is a plain fetch call inside the current round and its output is never read. Reviews are read only from the part of the output the reviews fetch produced (a body that quotes a review header is never read as a review; an output that cannot be told apart is counted unrecognised). One review is one round whatever its id form: the round is keyed by the numeric id once any fetch showed it, and a `PRR_` id (the marker's, `gh pr view`'s) is an alias of it, tied by the submission time and commit its own output shows. Each round and each fetch call carries its window's messages, tool calls, wall clock, model and the four token fields (never summed; usage once per `message.id`). Records nothing and fails open. |
| `libs/pr_round_record_lib.py`     | Records one pull request's review rounds, and the feedback fetch calls inside them, to the shared metrics store (`metric_id` `pr-review-rounds`, event types `pr_round` and `pr_feedback_fetch`), from what `libs/pr_round_cost_lib.py` found in a session transcript (used as it is, never edited) plus what GitHub says through an injectable `gh` call: the matching Copilot review's id, effort, inline-comment count and open-issue count, the push time (the earliest check suite for the reviewed commit) and the wait from it, and the PR's size. Every row also says which repository it is from (`repo`, `repo_source`: `owner/name` from the given `--repo` or the checkout's remote, else the session's project folder name marked `project`, else null), and each `copilot` round says whether the codebase-reviewer was used while its feedback was answered (`local_reviewer_used`, per round: true when a `local` round falls between it and the next Copilot round). Idempotent through `MetricsStore.record_if_absent` (check and insert in one write transaction, keyed on PR, review id and call time; the repository and reviewer fields are in no key), so a session end and a backfill over the same transcript never double-count. Fails open: a failed `gh` call leaves those fields null and is reported, an unreadable store stops the run and is reported, nothing is raised. See [Shared metrics store](metrics.md#the-pr-review-rounds-events). |
| `tools/record_pr_rounds.py`       | CLI behind that: `--transcript`, `--pr`, optional `--repo`, `--merge-time`, `--db`, `--dry-run`, `--format json`. Run it from a checkout of the PR's repository. Re-running over the same transcript writes nothing. |
| `libs/pr_round_report_lib.py`     | Read-only report over those `pr-review-rounds` rows (SQLite read-only URI mode, never creates the database): per repository, the Copilot rounds answered with the codebase-reviewer (`local_reviewer_used` true) against those answered without it (false), each of the four token fields on its own (rounds, total, median, range), and the `local` rounds that name their pull request summed apart as the reviewer's cost (the ones that name none are a separate ambiguous group, outside the cost, since one call is a row under every pull request the session fetched feedback for). Groups rounds, not pull requests (a round several sessions saw is one, each field summed); a project-folder row and a row with no repository are groups of their own, and a row with no flag (written before it existed) is `unknown`, never false. Stdlib only. See [Shared metrics store](metrics.md#the-pr-review-rounds-events). |
| `tools/pr_round_report.py`        | CLI behind that: `--db`, `--repo`, `--exclude-open`, `--json`. Prints the report; for the cut-off and like-for-like rules, `EVALUATION.md`'s Track G has the queries. |
| `libs/pr_round_backfill_lib.py`   | Backfills `pr-review-rounds` from the main-session transcripts of a project that still exist (Claude Code deletes old ones): lists the `<session id>.jsonl` files directly in the project folder (never subagent transcripts), finds the PR numbers each fetched feedback for (commands, the `pr-feedback-fetch` marker, `review` calls; a lead only, `libs/pr_round_cost_lib.py` decides), looks each PR up for the time that ends its last window (merge, or closing; never past the transcript's own last line) and records through `libs/pr_round_record_lib.py`, unchanged. A dry run by default; a PR still open is skipped (its last window would be stored as open and never corrected) unless asked for; a PR that cannot be looked up is reported and skipped; two transcripts sharing a tool-use id (a resumed session copied into a new file) are reported. Transcripts are only ever opened for reading. See [Shared metrics store](metrics.md#backfilling-from-the-transcripts-that-still-exist-toolsbackfill_pr_roundspy). |
| `tools/backfill_pr_rounds.py`     | CLI behind that: `--project-dir`, `--repo`, `--write` (without it, a dry run that writes nothing and does not open the database), `--include-open`, `--db`, `--format json`. Run it with `python -I`. Re-running writes nothing twice. |
| `libs/context_breakdown_lib.py`   | Shared, dependency-free itemization of a subagent transcript's context: request 0 split into prompt, tool definitions, skill list, CLAUDE.md files and the rest (in tokens that add up to the API's count), and each later request's growth split by the class of text that entered it, with tokens per character fitted from the API's own counts. Also lists whole-file Reads. Fails open. See [Shared metrics store](metrics.md#what-a-subagent-starts-with-and-why-its-context-grows-toolscontext_breakdownpy). |

| `libs/copilot_review_poll_lib.py` | Bounded wait for Copilot's review of one exact commit on a PR, used by `/cr-gh-autowork`'s subagent prompt: `NOT_YET` or the new review ids, at most about three minutes per call so the subagent's prompt cache stays warm. Stdlib only; the `gh` call is injectable for tests. |
| `tools/poll_copilot_review.py`    | CLI behind that: `--pr`, full 40-character `--head-sha`, `--me`, `--seen`. Prints `review:<id>` lines or `NOT_YET`. |
| `libs/qdrant_ingest_lib.py`       | Shared, dependency-free chunking logic. `.md`/`.mdx` chunk by heading. Chunks are cut by a `TokenBudget` (the embedding model's usable window and a token overlap, plus a callable giving each token's character span) over the file as a stream of characters, whatever its line structure. Within the last half of the budget a cut prefers, in order, a markdown heading (`.md`/`.mdx`; `#` headings and setext headings, a line of text underlined with `==` or `--`), a safe code boundary (curly-brace languages: `.cs`, `.ts`/`.tsx`, `.js`/`.jsx`, `.java`, `.go`, `.c`/`.h`/`.cpp`/`.hpp`, `.php`, `.swift`, `.kt`, `.scala`, `.rs`, via a lightweight brace/bracket-depth heuristic; and `.py`), a newline, whitespace, and then the exact budget; every other file type goes straight to a newline. Chunks are not stripped, and each carries `line_number` and `char_range`. The older line-window chunkers remain for callers that pass no budget (unit tests of the pure functions); no indexing entry point uses them. Also the versioned sync-manifest format (with an additive list of files a rebuild kept but did not scan), `chunk_position` (reads the new and the old `line_range` metadata) and `format_largest_files`. Used by both files below — keeps them from drifting apart. |
| `libs/upgrade_lib.py`             | Shared logic behind `tools/setup_project.py upgrade` — a config-migration tool for an ALREADY-configured project: unlike `init` (above), which resets every toolkit-owned setting to whatever flags that run passes, `upgrade` compares the target's current `.mcp.json`/`.claude/settings.json` against a fixed, ordered list of named, individually-detectable config gaps (`MIGRATIONS`), tells the user about each pending one, and applies only the ones they approve (every pending one with `--auto-yes`; `--dry-run` previews with nothing written). Each `Migration`'s own `detect` is the sole source of truth for whether it still applies, so re-running is always safe. Also ships one repo-file migration (`REPO_MIGRATIONS`), which removes an old-format sync manifest so the next `cb_indexer_sync_repo` rebuilds the index. Ships 12 config migrations covering gaps in the memory-bank server config, the removal of the `codebase-indexer` block's old `MEMORY_BANK_COLLECTION` copy (`codebase-indexer-memory-bank-collection-dropped`), session-id hook registration (add and stale-registration removal), the SessionEnd PR-round capture hook being added (`pr-round-capture-hook-missing`), the `compact` block's move from the third-party Qdrant MCP server's console script to this repo's own server (carrying over the compact settings, and pinning the compact embedding model to `BAAI/bge-small-en` where compacts predate that setting), the compress hook's rename from `compress_bash_output.py` to `compress_output.py`, the compress hook matcher gaining the `compact` server's compact tools, the opt-in `analytics` server block being offered to a project that already tracks savings, the removal of the unused `CLAUDE_RUNWAY_SAVINGS_DB` key from the `local-compress` block (after any carry-over into `analytics`), and the rewrite of each server's script path from `tools/` to `mcpservers/` (`mcp-server-scripts-moved`), and then the `codebase-indexer` script's rename from `ingest_mcp_server.py` to `codebase_indexer_mcp_server.py` (`codebase-indexer-script-renamed`). Separately from the migrations, `run_upgrade` can offer the opt-in `codebase-reviewer` server once (`offer_reviewer_fn`, writing it with `REVIEWERS_FILE` blank), but `tools/setup_project.py` passes none while the server is unreleased, so `upgrade` never asks. `upgrade` then also refreshes skills already installed under `~/.claude/skills/` (`--skills-dir` to override) that differ from the shipped ones, keeping an installed copy's own frontmatter, and never installs a skill that is not there. |
| `tools/ingest_to_qdrant.py`       | Standalone CLI script for one-off/manual full indexing. Prints progress to the terminal; use this for the first big index of a repo. `--write-manifest` (opt-in) also writes `cb_indexer_sync_repo`'s manifest, so the first `cb_indexer_sync_repo` after it re-embeds only what changed; see [Known limitations](known-limitations.md). |
| `mcpservers/codebase_indexer_mcp_server.py`      | MCP server exposing nine `cb_indexer_*` tools Claude can call directly: `cb_indexer_index_repo`, `cb_indexer_sync_repo`, `cb_indexer_preview_index`, `cb_indexer_get_collection_info`, `cb_indexer_find_in_collection`, `cb_indexer_set_collection_description`, `cb_indexer_list_collections`, and `cb_indexer_find_repo`/`cb_indexer_store_repo` (search and save notes in this project's own collection; they were `qdrant-find`/`qdrant-store` on the `compact` server, and call into `libs/qdrant_connector.py`). `cb_indexer_find_in_collection`/`cb_indexer_list_collections` let a session in one project search a DIFFERENT already-indexed repo's collection by exact name — e.g. searching a backend repo's collection from a frontend repo's session — since `cb_indexer_find_repo` itself is locked to this project's own collection (see [Cross-repo lookups](cross-repo-lookups.md)). `cb_indexer_index_repo`/`cb_indexer_sync_repo` mark the collections they create and refuse outright an existing collection without that mark (the shared memory-bank collection, a compact collection or anything else, whatever its name; see `libs/qdrant_code_index_marker.py`), and their reset/delete paths always preserve memory-bank points. They, and `cb_indexer_preview_index` (which therefore loads the embedding model), chunk by the model's token window and report per-file progress and the largest files; `cb_indexer_sync_repo`'s first run after an update rebuilds the index, cleans up and records the files it kept outside its scan (see [Known limitations](known-limitations.md)). `cb_indexer_index_repo` writes `cb_indexer_sync_repo`'s manifest when it starts from a clean slate in this project's own collection, so the two tools hand over to each other without a second full embed. |
| `libs/qdrant_model_check.py`      | Shared embedding-model mismatch check used by `cb_indexer_find_in_collection`, `cb_indexer_index_repo`, `cb_indexer_sync_repo` (all above), and `memory_bank_lib.py` (below) — relocated out of `codebase_indexer_mcp_server.py` so callers can't drift apart. Fails open on a network error/inconclusive shape by default; returns a loud, actionable error only on a definitive schema-level mismatch. `cb_indexer_index_repo(reset=True)`'s and `cb_indexer_sync_repo`'s pre-delete checks opt into `fail_closed=True` instead, since an inconclusive result there must block a destructive delete, not silently permit it. |
| `libs/qdrant_credentials.py`      | The one rule for which API key goes with a tool call's `qdrant_url`: an explicit key always wins, the configured `QDRANT_API_KEY` is used only when the URL is the configured `QDRANT_URL`, and any other URL gets no key. Used by every `codebase_indexer_mcp_server.py` tool and every `compact_mcp_server.py` compact tool (`compact_store`, `compact_find`, `compact_prune`) taking `qdrant_url`/`qdrant_api_key`, by `transfer_memories`, and by `tools/ingest_to_qdrant.py`'s `--qdrant-url`/`--qdrant-api-key`, so a prompt-injected or mistyped URL cannot collect the configured credential. Its `same_endpoint` (a trailing slash is the only normalisation) is also how `codebase_indexer_mcp_server.py` decides a call targets this project's own collection, which owns the sync manifest and its lock. Stdlib only. |
| `libs/qdrant_index_prep.py`       | Pre-index collection preparation shared by `cb_indexer_index_repo` and `tools/ingest_to_qdrant.py` — `--reset`'s model check and memory-bank-preserving delete, or the `metadata.file_path` index backfill — with every Qdrant call retry-wrapped. |
| `libs/sync_manifest_lib.py`       | The sync manifest's read, atomic write and discard, the baseline a full index records, and `ManifestLock`, the per-checkout lock that keeps two runs from using the manifest at once, shared by `mcpservers/codebase_indexer_mcp_server.py` (`cb_indexer_sync_repo`, `cb_indexer_index_repo`) and `tools/ingest_to_qdrant.py` (`--write-manifest`) so the two cannot drift apart on a file every later `cb_indexer_sync_repo` trusts. Same format as `libs/qdrant_ingest_lib.py` defines. |
| `libs/qdrant_retry.py`            | Retry-once wrapper for a dropped Qdrant connection, used by `cb_indexer_sync_repo`/`cb_indexer_index_repo` — see the vpnkit bullet in [Known limitations](known-limitations.md) for why it exists. |
| `libs/qdrant_embeddings.py`       | The repo's own `FastEmbedProvider`, wrapping `fastembed.TextEmbedding` (replaces the one the third-party Qdrant MCP server package provided). Keeps the on-disk vector name (`fast-` plus the model's basename) so existing collections stay readable. Loads the model from the local cache first, with no network access, and only downloads on a cold cache, so no server config needs `HF_HUB_OFFLINE`. Also the one place that reads the model's token window (`build_token_budget`, which reaches into private fastembed attributes and raises an error naming the model when it cannot read them). |
| `libs/qdrant_connector.py`        | The repo's own async `QdrantConnector` and `Entry` (replace the ones the third-party Qdrant MCP server package provided): `store`, `search` and `ensure_collection_exists`, with the client, default collection and provider public. Keeps the on-disk format: one named cosine vector, payload `{document, metadata}`, `uuid4().hex` ids. An optional `collection_metadata` is written in the request that creates a collection (the codebase-indexer's ownership mark), and an optional `existing_collection_check` is run on the current metadata of any collection it writes into without creating it. |
| `libs/qdrant_batch_store.py`      | Batched Qdrant writes for indexing. Retrying alone didn't fix the indexing failures, because the cause was a hard resource ceiling (ephemeral ports/vpnkit) rather than transient drops, so writes are batched instead. |
| `libs/cache_db.py`                | Shared, disposable SQLite store (`CLAUDE_RUNWAY_CACHE_DB`, default `~/.claude/claude-runway/cache.db`), deliberately separate from `savings.db` so clearing a cache can never delete data meant to be kept. Callers own their tables; this module only provides the connection. See [Environment variables](environment-variables.md). |
| `libs/qdrant_compact_marker.py`   | Shared collection-metadata marker that `compact_store` writes on conversation-compact collections and `cb_indexer_find_in_collection`/`cb_indexer_list_collections` read, so compacts are never listed or searched as if they were codebases. One module so the writer and the readers can't drift apart. |
| `libs/qdrant_code_index_marker.py` | The codebase-indexer's own collection-metadata mark (`claude_runway_kind: code-index`), written when `cb_indexer_index_repo`, `cb_indexer_sync_repo`, `cb_indexer_store_repo` or `tools/ingest_to_qdrant.py` creates a collection, and `check_code_index_ownership`, the one guard all of them (and the startup `COLLECTION_DESCRIPTION` sync) run before writing: an existing collection without the mark (or with the compact marker) is refused, whatever its name, failing closed when its metadata cannot be read. `metadata_ownership_error` is the metadata-only half, which `QdrantConnector` (`existing_collection_check`) re-applies to a collection it did not create before every batch, in case one appears, is recreated or is marked compact under that name after the guard ran. An unmarked collection indexed before the mark existed is adopted when it holds indexed file chunks and no memory-bank or compact points. |
| `libs/qdrant_collection_hints.py` | Persistent cache for `cb_indexer_list_collections`' per-collection hints, stored in the shared cache DB above and keyed by `(qdrant_url, collection)` so two Qdrant instances can't collide. Needed because MCP servers restart every session. See [Cross-repo lookups](cross-repo-lookups.md). |
| `libs/memory_bank_lib.py`         | Shared logic behind `mcpservers/memory_bank_mcp_server.py` — `remember`/`recall`/`forget` write into ONE shared Qdrant collection across every project (not each project's own code index), tagged `metadata.repo` per writing project (or the reserved `"general"` sentinel for cross-project knowledge) so lookups default to precise per-project scope with an explicit override to broaden.
