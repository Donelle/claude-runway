# Prerequisites

- A running Qdrant instance (local or remote), reachable at a URL — required for piece 1
- LM Studio (https://lmstudio.ai) running locally with a model loaded — required for piece 2, optional otherwise. On a Windows laptop with both an Intel integrated GPU and a discrete NVIDIA GPU (a common corporate hardware split), LM Studio may fail to use the discrete GPU by default — see [Windows GPU setup for LM Studio](windows-setup.md) for the fix.
- **Network access to `huggingface.co` (or its `storage.googleapis.com` mirror) the first time you index a repo** — piece 1's embedding step (`FastEmbedProvider`, from the `mcp_server_qdrant`/`fastembed` packages) downloads the ONNX embedding model weights on first use, then caches them locally. This is a one-time bootstrap on a machine, not a per-run dependency for the IN-PROCESS `FastEmbedProvider` path (`codebase-indexer`/`ingest_to_qdrant.py`): verified directly that constructing the provider against an already-cached model makes zero network calls there. The cache lives at `FASTEMBED_CACHE_PATH` (default `~/.claude/claude-runway/fastembed-cache`), a persistent location this toolkit controls rather than `fastembed`'s own OS-temp-dir default, so a reboot or periodic temp cleanup no longer reintroduces this network dependency. This is set automatically, no configuration needed, for the `codebase-indexer` MCP server and `ingest_to_qdrant.py`'s CLI usage.
  **This does NOT hold for the separate, standalone `qdrant` MCP server** (the third-party `mcp-server-qdrant` process that `qdrant-find`/`qdrant-store` run through) — its own startup calls `fastembed.TextEmbedding.__init__` → `huggingface_hub.snapshot_download`, which always makes a live HTTP call to resolve the revision/file listing before falling back to the local cache, EVEN on a cache hit, unless `HF_HUB_OFFLINE=1` is set. Reproduced directly: 59.6s to answer the MCP `initialize` handshake with the network round-trip vs. 2.0s with `HF_HUB_OFFLINE=1` set, against the exact same already-cached model — slow enough on an unreliable network (VPN, proxy, unauthenticated HF Hub rate limiting) to exceed Claude Code's 30s MCP connection timeout and surface as `qdrant (CONNECT_TIMEOUT)`, even though the server would have come up fine a few seconds later using purely local files. `tools/setup_project.py`/`claude-runway-setup init` now handles this automatically on every real (non-`--dry-run`) run: it warms the fastembed cache with a bounded retry loop, then confirms that it genuinely loads with zero network access by reconstructing the model with `local_files_only=True` passed as an explicit constructor argument — NOT by setting `HF_HUB_OFFLINE` in the environment and reconstructing, which doesn't work: `huggingface_hub.constants` reads `HF_HUB_OFFLINE` from the environment exactly once, at whichever moment that module is first imported (already triggered by the warm-up step just before), so mutating it afterward has no effect on `huggingface_hub`'s own offline check for the rest of that process (found in review, reproduced directly). `local_files_only=True` is a plain per-call argument `fastembed` threads straight through to `huggingface_hub.snapshot_download`'s own network-call gate instead, so it works correctly regardless of import order. Only once that confirmation succeeds does setup write `HF_HUB_OFFLINE=1` into the generated `.mcp.json`'s `qdrant` server env block (a separate, later process, where setting it before `huggingface_hub` is ever imported works correctly) — never unconditionally, since that would break a genuinely first-time setup (empty cache) outright with no network fallback at all. A rerun on a machine whose cache later goes missing/incomplete automatically falls back to re-warming rather than leaving `HF_HUB_OFFLINE=1` stranded against an empty cache.
- Python 3.12+ for the Qdrant codebase memory piece (`tools/ingest_mcp_server.py`, `tools/ingest_to_qdrant.py`) — project policy minimum; the dependency chain supports >=3.10
- Python 3.11+ for the local compression piece (`tools/compress_mcp_server.py` and hooks) — project policy minimum; the dependency chain supports >=3.10
- [uv](https://docs.astral.sh/uv/) — creates the virtual environment and installs dependencies; required on Linux, recommended on macOS
- Claude Code
