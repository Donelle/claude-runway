# Prerequisites

For hardware sizing and compression-model candidates, see the [Local workstation and model guide](workstation-guide.md), including capacity planning for future development model routing.

- A running Qdrant instance (local or remote), reachable at a URL — required for piece 1
- LM Studio (https://lmstudio.ai) running locally with a model loaded — required for piece 2, optional otherwise. On a Windows laptop with both an Intel integrated GPU and a discrete NVIDIA GPU (a common corporate hardware split), LM Studio may fail to use the discrete GPU by default — see [Windows GPU setup for LM Studio](windows-setup.md) for the fix.
- **Network access to `huggingface.co` (or its `storage.googleapis.com` mirror) the first time a model is used on a machine** — every process that embeds text (`FastEmbedProvider` in `libs/qdrant_embeddings.py`, built on the `fastembed` package: the `qdrant`, `codebase-indexer` and `memory-bank` MCP servers, and `ingest_to_qdrant.py`) downloads the ONNX embedding model weights on first use, then caches them locally. This is a one-time bootstrap on a machine, not a per-run dependency: the provider loads from the cache first with no network access at all (`local_files_only=True`, which `fastembed` passes straight to `huggingface_hub`), and only goes to the network when the cache does not hold the model. That matters because a cache HIT through `fastembed`'s normal path still makes a live HTTP call to huggingface.co to resolve the revision, measured at 59.6s on a slow network (VPN, proxy, unauthenticated HF Hub rate limiting) against 2.0s without it, long enough to exceed Claude Code's 30s MCP connection timeout. No `.mcp.json` entry is needed for this (there is no `HF_HUB_OFFLINE` to set), and the servers also load their models on first use rather than at startup, so a slow or missing network can never delay the MCP handshake. The cache lives at `FASTEMBED_CACHE_PATH` (default `~/.claude/claude-runway/fastembed-cache`), a persistent location this toolkit controls rather than `fastembed`'s own OS-temp-dir default, so a reboot or periodic temp cleanup no longer reintroduces the download. This default is set in code by each process; no configuration needed.
- Python 3.12+ for the Qdrant codebase memory piece (`mcpservers/qdrant_mcp_server.py`, `mcpservers/ingest_mcp_server.py`, `tools/ingest_to_qdrant.py`) — project policy minimum; the dependency chain supports >=3.10
- Python 3.11+ for the local compression piece (`mcpservers/compress_mcp_server.py` and hooks) — project policy minimum; the dependency chain supports >=3.10
- [uv](https://docs.astral.sh/uv/) — creates the virtual environment and installs dependencies; required on Linux, recommended on macOS
- Claude Code
